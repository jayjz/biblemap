## Publication decisions and indexing

The existing `publication-scope.json` contains 45 explicit editorial/utility routes: 43 provisional candidate pages, one internal demo, and one excluded experiment. **There are no accepted public pages.** `publication-decision.json` remains `pending`. Nothing in this implementation supplies creator acceptance, changes maturity, or authorizes production.

Indexing requires all of: a classified route, `complete` maturity, inclusion in an accepted creator decision, no explicit `indexing: noindex`, a self canonical, and a non-preview build. Existing production prebuild/postbuild digest validation remains mandatory. Provisional material stays noindex even if a future decision accepts its limited publication. New routes fail closed. A completed route can deliberately remain noindex using the optional field in the existing registry.

The registry has two optional, validated SEO properties: `indexing: "noindex"` and `canonicalRoute`. The only alias is `/human-story/` -> `/`; it retains its URL and useful rendered content, has distinct descriptive metadata, and stays noindex. Alias targets must be selected, self-canonical routes; alias chains are rejected. There is no parallel publication registry.

## Before and after

- Before: `/explore/` inherited the generic site title/description; most pages had no canonical, reading alternatives lacked descriptions, and social tags often described the homepage instead of the page. `/nineveh/` and `/explore/` could inherit indexability despite provisional status. After: one shared policy supplies explicit canonical, robots and matching page-level Open Graph/Twitter metadata across static and dynamic pages; root defaults fail closed.
- Before: no robots or sitemap metadata routes. After: official Next metadata file conventions, `force-static`, and a publication-derived sitemap compatible with `output: export`. No invented last-modified dates or priorities.
- Before: `/demo/` and `/experiments/nineveh/` exported 404 HTML under directories served as HTTP 200. After: postbuild removes those route artifacts unless their existing local-review flags are explicitly enabled. It also removes `/_not-found/`, which the base preview independently served as HTTP 200. The ordinary export exposes genuine 404s.
- Before: internal links sent visitors to the duplicate portal URL. After: return links and thread links use `/` and `/#paths`, while inbound `/human-story/` links remain usable.
- Before: a client component imported the `/explore/` route module. After: the server route owns metadata and no-JavaScript context; reusable WebGL UI stays in `ExploreClient`, including legacy root navigation.

The initial failing audit is retained in [before.json](../../artifacts/seo-routing/before.json). Its title-count checks included SVG title elements and were subsequently corrected to inspect head titles only; its findings should not be treated as an unqualified defect count.

## Canonicals, routing and legacy state

The established trailing-slash policy remains in Next config and is explicit in Vercel config. Slashless page paths redirect once to slash-terminated paths. `index.html` representations redirect to directory paths in the loopback test host; a genuine hosted 404 is also valid for these noncanonical file paths. The base preview returns 404 for `/jonah/index.html`; it is not an established editorial URL requiring migration. Hosted equivalents must be checked on the actual preview because Vercel routing can differ from a filesystem server. `cleanUrls` normalizes HTML extensions without migrating established editorial paths. No domain, DNS, alias or canonical-origin changes were made.

Root tracking parameters, `?explore=1`, `?place=...`, `?event=...` and historical fragments still select legacy atlas/Nineveh states. They are state representations, not separate sitemap pages. `/explore/` has its own canonical; `/nineveh/` remains a separate narrative entrance; `/human-story/jonah/` remains a sourced reading distinct from the full `/jonah/` reader. Fragment navigation is tested in the browser because fragments do not reach HTTP servers. All 43 routes are also fetched with a tracking query to check canonical stability.

## Internal links, semantics and source architecture

The five existing worlds group Scripture, ancient witnesses, saints, places/material evidence, and interpreters. Three authored threads cross these groups without implying historical itineraries or continuous influence. Reading-room connections and source disclosures preserve evidence distinctions. Crawlable initial-HTML navigation, related readings, alternate reading views and source links already provide topical architecture; additional thin index pages would duplicate that work.

The audit resolves every internal anchor destination path and downloadable asset link, rejects unknown/internal/experimental page links, and reports incoming links. It allows same-document anchors on the preserved alias. There are no orphan self-canonical candidate pages. The deliberate portal alias has no canonical incoming navigation. All candidate pages provide meaningful initial HTML and one H1 with JavaScript disabled; the atlas supplies an honest no-JavaScript explanation and links to server-rendered reading. The map itself still requires JavaScript/WebGL.

Existing reading-location navigation acts as a breadcrumb where the hierarchy helps. No invented geographic breadcrumb or schema hierarchy was added. Desktop/mobile, keyboard focus, reduced motion, empty search, missing-media fallback, source disclosures and no-JavaScript reading are covered by existing browser suites. This task preserves narrative prose, Scripture, artwork and source records.

## Structured data

The root page exposes a minimal `WebSite` using the visible BibleMap identity and existing canonical URL. No Organization, authors, credentials, dates, ratings or historical authority were invented. Article/CreativeWork and BreadcrumbList were evaluated but deferred: these mixed narrative/source interfaces need an explicit editorial authorship model and a consistent visible hierarchy before richer types would add reliable meaning.

The audit parses JSON-LD, checks context/type and the actual supported WebSite properties, and rejects unsupported types until their validator is extended. Adversarial malformed JSON is rejected. This establishes JSON syntax and the implemented Schema.org subset; it does not claim Google rich-result eligibility or a Rich Results Test result.

## Jonah regression diagnosis

Base CI run [42371029404](https://github.com/jayjz/biblemap/actions/runs/42371029404) passed source, unit, lint, type and adversarial-export checks. Its ordinary browser suite reported 233 passed, one skipped, and exactly two failures (desktop/mobile Jonah): same-origin GET `/index.txt?_rsc=...`, `net::ERR_ABORTED`. Destination assertions had passed before the final network assertion. The untouched baseline passed both targeted tests locally, showing the cancellation is timing dependent.

Installed Next.js 16.4.5 `fetch-server-response.js:95` changes static-export Flight requests to `index.txt` or `.txt`; `app-router-headers.js` defines `_rsc`. The documented static export model emits RSC payloads alongside HTML for client navigation. There was no evidence of a missing destination, HTTP error, missing asset or failed rendered page in those CI failures.

The collector now separates only same-origin **GET fetch** requests with a nonempty actual `_rsc` marker, a `.txt` pathname and the exact `net::ERR_ABORTED` failure. It removes the prior broad document/HEAD exception. Cancellations remain attached as test diagnostics. All HTTP 4xx/5xx and other failures remain strict. Jonah still verifies destination URL and meaningful rendered content after returning home. A new browser regression deliberately aborts a real navigation and serves HTTP 503 (including an RSC-marked URL), proving that the strict assertion still rejects both. Unit cases cover cross-origin, missing/empty marker, wrong method, script/stylesheet/document requests and other failure text.
